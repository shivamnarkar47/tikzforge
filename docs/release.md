# Releasing TikzForge

TikzForge ships as a Tauri desktop app for Linux (AppImage, `.deb`) and
Windows (NSIS installer), with an in-app auto-updater. Releases are
driven entirely by **git tags** — pushing a `v*` tag triggers the
`Release` GitHub Actions workflow, which builds both platforms and
publishes a GitHub Release.

## Versioning

Semantic versioning (`MAJOR.MINOR.PATCH`). A **minor** bump signals new
features; a patch bump signals fixes. The version string must be kept in
sync across four files before tagging:

| File | Field |
|------|-------|
| `package.json` | `"version"` |
| `src-tauri/tauri.conf.json` | `"version"` |
| `src-tauri/Cargo.toml` | `version =` |
| `src-tauri/Cargo.lock` | `version =` under `name = "tikzforge"` |

## Release checklist

1. **Bump the version** in all four files above (e.g. `0.1.4` → `0.2.0`).
2. **Commit** the bump:
   ```bash
   git add -A
   git commit -m "chore: bump version to 0.2.0 (minor release)"
   ```
3. **Tag** the commit with a `v`-prefixed version:
   ```bash
   git tag v0.2.0
   ```
4. **Push** the commit and the tag:
   ```bash
   git push origin master --tags
   ```
   Pushing the tag triggers `.github/workflows/release.yml`.

## What the workflow does

`.github/workflows/release.yml` runs on `push: tags: v*` across two
matrix platforms (`ubuntu-latest`, `windows-latest`):

1. Checks out the repo, sets up bun + Rust, caches Rust build artifacts.
2. Installs Linux system dependencies (GTK, WebKit, etc.).
3. `bun install --frozen-lockfile`.
4. Caches and stages the bundled Tectonic engine
   (`scripts/prepare-texlive.sh linux|windows`).
5. Verifies the staged engine (`scripts/generate-tauri-config.sh --force`).
6. Builds the app (`bun run tauri build`).
7. Publishes assets to the GitHub Release via `softprops/action-gh-release`:
   - Linux: `*.AppImage`, `*.deb`
   - Windows: `*.exe` (NSIS)

The release is created automatically from the tag; no manual GitHub UI
step is required.

## Auto-updater

The app includes Tauri's updater plugin. `tauri.conf.json` points the
updater at:

```
https://github.com/shivamnarkar47/tikzforge/releases/latest/download/latest.json
```

For in-app update checks to work, each release must ship a `latest.json`
manifest (generated by Tauri's updater during build when signing keys are
configured). The app's "Update status" indicator in the header reflects
`checking / available / up to date`.

## AUR (Arch Linux)

The `packaging/aur/` directory contains PKGBUILDs for AUR distribution.
Bump the `pkgver` and update checksums there when cutting a release, then
push to the AUR git remote separately.

## Quick reference

```bash
# Minor release example
sed -i 's/"version": "0.1.4"/"version": "0.2.0"/' package.json src-tauri/tauri.conf.json
sed -i 's/^version = "0.1.4"/version = "0.2.0"/' src-tauri/Cargo.toml
# also update src-tauri/Cargo.lock's tikzforge entry
git add -A && git commit -m "chore: bump version to 0.2.0 (minor release)"
git tag v0.2.0 && git push origin master --tags
```
